# API 개발 가이드라인

## 1. Next.js API Routes (`/pages/api`)

### 역할: Backend-for-Frontend (BFF)
- 프론트엔드와 밀접하게 관련된 로직을 처리합니다.
- 서버사이드 렌더링(SSR) 또는 정적 사이트 생성(SSG)을 위한 데이터를 페칭(fetching)하는 데 사용될 수 있습니다.
- 외부 Express API를 호출하여 프론트엔드에 필요한 형태로 데이터를 가공하거나 조합하여 전달하는 역할을 합니다.
- 간단한 폼 제출 처리, 쿠키/세션 관리 등 UI를 직접적으로 지원하는 간단한 기능에 적합합니다.
- **원칙:** 복잡한 비즈니스 로직이나 데이터베이스에 직접 접근하는 로직은 포함하지 않는 것을 원칙으로 합니다. 모든 핵심 로직은 Express API를 통해 처리해야 합니다.

## 2. Express API (`/server`)

### 역할: 핵심 비즈니스 로직 서버
- 데이터베이스 CRUD(생성, 읽기, 업데이트, 삭제) 작업을 전담합니다.
- 사용자 인증(로그인, 회원가입) 및 인가(JWT 발급/검증 등)를 처리합니다.
- 베팅, 정산, 경기 결과 업데이트 등 애플리케이션의 핵심 비즈니스 로직을 수행합니다.
- 외부 스포츠 데이터 API와의 통신 및 데이터 수집, 가공, 저장을 담당합니다.
- WebSocket 연결 관리 및 실시간 데이터 브로드캐스팅을 처리합니다.
- **원칙:** 프론트엔드의 UI 구조나 상태에 의존하지 않는, 순수한 데이터와 비즈니스 로직을 다룹니다. API는 독립적으로 존재하며 어떤 종류의 클라이언트와도 통신할 수 있어야 합니다.
